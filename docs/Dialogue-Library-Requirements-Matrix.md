# 1. 矩阵定位

本矩阵采用 AI Agent 主导实现的交付方式，不设置开发人天、预估耗时、开发人数、开始日期和完成日期，不以人工工期作为任务完成依据。

每项需求以“来源 → 前置契约 → 交付物 → 可执行验证 → 证据 → 人工验收”追踪。未形成技术设计时，只建立产品级交付单元，不假装已经具备实现条件。

本矩阵保留完整功能清单的编号、优先级、决策状态和验收规则。当前没有功能实现与测试证据，所有执行状态均为待设计或待评估，不能解读为已完成或已批准。

## 1.1 单元粒度

- 当前一条矩阵记录对应一个功能编号，方便完整追踪。
- 技术设计完成后，一个功能可以拆成多个 Agent 任务；每个任务应有明确输入、边界、输出、验证命令和证据。
- 不按“几人天以内”拆分，按是否可独立验证、回滚及控制改动范围拆分。
- 一个任务引用多个需求时需逐项提供证据，不以合并任务掩盖未实现需求。

## 1.2 三类状态分离

- 产品决策：基线、部分待定、建议、可选，沿用功能清单。
- 执行状态：待评估、待设计、可领取、实现中、待验证、待验收、完成、阻塞。
- 验收结果：未执行、通过、失败或经明确批准不适用。

AI Agent 完成代码不等于需求完成。完成必须关联真实测试输出、产物或可复核操作记录；未运行的验证不得标记通过。

# 3. 产品级依赖与可交付边界

| 交付域 | 依赖的契约或数据 | 可独立验证的产物 | 禁止隐含依赖 |
| --- | --- | --- | --- |
| 输入与去重 | 输入、配对、哈希和冲突契约 | 有效输入与重复/异常结果 | 不依赖 ASR、Embedding、视觉模型 |
| 基础建库 | 稳定素材标识、存储和结构化台词契约 | 标准三件套与基础记录 | 不要求预处理原视频或 AI 补齐信息 |
| 媒体预览 | 原件访问、媒体属性与时间基准 | 缩略图、可播放原件或兼容预览 | 不覆盖原件，不修改台词时间基准 |
| 人工管理 | Asset、Dialogue 和更新接口 | 可编辑、分类、删除的素材 | 不以 AI 成功作为可管理门槛 |
| 关键词检索 | 可检索工作数据及更新契约 | 台词命中、筛选及全文索引 | 不依赖向量模型 |
| 可选 AI 增强 | 已有素材、选定输入与模型契约 | 分别生成向量、情绪、视觉结果 | 三类能力不强制串行、不阻塞基础库 |
| 外部集成 | 版本明确的接口与文件交付契约 | 非 UI 客户端可复核调用 | 不宣称未实测的剪辑系统兼容 |
