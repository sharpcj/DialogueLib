# 1. 范围与标记说明

## 1.1 产品基线

- 标准输入：Video + SRT。
- 标准化存储：Video + SRT + JSON。
- 管理单位是视频 Asset，一个 Asset 对应零条或多条 Dialogue；零条可用于处理未完成，不自动表示无台词内容符合完整标准。
- 基础建库完全不依赖 AI 模型和在线 API。
- 用户确认导入后执行固定流程，不额外增加强制人工收录审批。
- ASR、OCR、已有字幕提取、人工字幕制作属于上游可选准备，不是固定入库步骤。
- 仅视频的资源允许接纳，但其状态、入口及与完整标准素材的展示关系待确认。
- 不要求用户预先统一视频格式、编码、分辨率或文件名。
- AI 增强失败不影响基础素材；任何分析与派生处理不覆盖原始视频。

## 1.2 优先级

- P0：基础素材库必备。
- P1：语义、内容理解及外部集成增强。
- P2：后续扩展。
- 未排期：可选能力或范围待确认，不计入当前承诺交付。

## 1.3 决策状态

- 基线：用户已明确的能力或实现该能力必要的业务分解；仍须评审细节，不表示文档已获批准。
- 部分待定：能力明确，但存在影响验收的规则待确认。
- 建议：为闭环提出的补充功能，不因列入本文自动成为已确认需求。
- 可选：非核心必经能力，需要另行决定是否实施。

表格中的验收要点描述预期行为，不代表已经实现或经过测试。标为建议、可选、部分待定的条目，应结合第 9 节完成范围确认后再形成开发承诺。

# 2. P0 基础素材库功能

## 2.1 素材选择与导入（IMP）

| 编号 | 功能 | 状态 | 业务规则与验收要点 |
| --- | --- | --- | --- |
| IMP-001 | 单素材文件导入 | 基线 | 选择视频及配套 SRT；不要求用户提供 JSON 或统一媒体属性。 |
| IMP-002 | 批量文件导入 | 基线 | 一次选择多组资源，分别反馈结果；单组异常不阻塞其他组。 |
| IMP-003 | 目录扫描 | 部分待定 | 扫描候选视频与字幕，用户确认后才提交；递归范围待定，不自动监控收录。 |
| IMP-004 | 视频与字幕配对 | 部分待定 | 可提出匹配候选，不能只因名字相近就强制绑定；多个候选时提示确认。 |
| IMP-005 | 配对人工调整 | 基线 | 用户可纠正视频与 SRT 的关联，不要求先修改文件名。 |
| IMP-006 | 导入确认 | 基线 | 显示将提交的资源和已知问题，用户确认后开始后台任务。 |
| IMP-007 | 仅视频资源接纳 | 部分待定 | 保留有效视频，显示字幕缺失；入口及正式列表规则待定，不自动调用 ASR。 |
| IMP-008 | 后续补充 SRT | 基线 | 为已有资源补充字幕，只更新相关台词、JSON 与索引，不重存相同视频。 |
| IMP-009 | 可选原始 JSON 输入 | 部分待定 | 可保存用户已有 JSON；字段导入与冲突规则待定，不将其作为必需输入。 |
| IMP-010 | 批次处理结果 | 基线 | 分别展示完成、重复、失败、待确认或待补全情况，不把所有项目统一显示成功。 |

## 2.2 校验与精确去重（VAL）

| 编号 | 功能 | 状态 | 业务规则与验收要点 |
| --- | --- | --- | --- |
| VAL-001 | 视频有效性检查 | 基线 | 检查可读取、媒体可解析等基本条件；损坏、加密或不支持时明确原因。 |
| VAL-002 | SRT 可解析性检查 | 基线 | 识别字幕条目、文本与时间；编码或语法问题明确反馈，不静默丢字。 |
| VAL-003 | 时间戳检查 | 部分待定 | 检查负值、起止关系、时长越界、乱序或重叠；不同异常的阻断级别待定。 |
| VAL-004 | 视频内容哈希 | 基线 | 以文件内容判断完全重复，不以文件名、路径或台词文本作为依据。 |
| VAL-005 | 批次内去重 | 基线 | 同批次相同视频不会重复形成存储和相同处理任务。 |
| VAL-006 | 库内去重 | 基线 | 命中已有视频时反馈关联素材，不重新保存相同视频。 |
| VAL-007 | 处理中资源去重 | 基线 | 重复提交同一视频时关联已存在任务，避免并发重复建库。 |
| VAL-008 | 重复资源的配套信息冲突 | 部分待定 | 新 SRT、JSON 或来源不静默丢弃或覆盖；具体比较与替换策略待定。 |
| VAL-009 | 校验问题反馈 | 基线 | 关联具体资源与步骤，区分警告、失败及需要人工决定的问题。 |

精确去重不承诺识别重新编码、加水印或稍有裁切的相同内容；该能力属于 P2。不同视频说出相同台词，应允许分别保存。

## 2.3 原始文件与派生资源管理（STO）

| 编号 | 功能 | 状态 | 业务规则与验收要点 |
| --- | --- | --- | --- |
| STO-001 | 原始视频保存与关联 | 部分待定 | 原始视频可追溯、不被覆盖；托管复制或外部引用的具体模式待定。 |
| STO-002 | 原始字幕保存 | 基线 | 导入 SRT 原件与结构化工作台词分离；人工修订不覆盖原件。 |
| STO-003 | 原始 JSON 保存 | 部分待定 | 如导入则保留原件，与系统生成的标准 JSON 区分。 |
| STO-004 | 标准三件套关联 | 基线 | Video、SRT、JSON 通过素材身份关联，不要求原始文件同名。 |
| STO-005 | 稳定素材标识 | 基线 | 标题修改、派生文件重建不改变素材身份；不可仅用文件名充当身份。 |
| STO-006 | 派生资源管理 | 基线 | 缩略图、预览与索引可区分、可重建，不冒充原始资源。 |
| STO-007 | 文件完整性检查 | 基线 | 识别文件缺失、不可读或内容与记录不符，显示受影响素材。 |
| STO-008 | 存储失败保护 | 基线 | 写入失败不显示完成；保留已保存原件及明确状态，允许后续恢复。 |
| STO-009 | 失效资源修复入口 | 建议 | 对路径失效或派生资源缺失提供定位、重新关联或重建入口；不得错误绑定其他视频。 |

## 2.4 媒体解析与预览资源（MED）

| 编号 | 功能 | 状态 | 业务规则与验收要点 |
| --- | --- | --- | --- |
| MED-001 | 媒体属性提取 | 基线 | 提取时长、容器、编码、分辨率、帧率、音轨等；展示无法取得的属性而非编造值。 |
| MED-002 | 缩略图生成 | 基线 | 为列表提供缩略图；失败可单独重试，不丢弃视频。 |
| MED-003 | 原视频预览检测 | 基线 | 可直接播放时使用原视频；不为格式统一而无条件转码。 |
| MED-004 | 兼容预览生成 | 基线 | 无法直接预览时按需生成兼容副本，原视频内容保持不变。 |
| MED-005 | 预览时间对应 | 基线 | 使用预览副本播放时，台词时间仍能正确定位，不产生无解释偏移。 |
| MED-006 | 原件与预览属性区分 | 基线 | 用户可区分原视频和预览副本，不能将预览分辨率写成原素材分辨率。 |
| MED-007 | 派生任务失败重试 | 基线 | 缩略图或预览失败仅重试相关步骤，不要求重新导入和全链路重跑。 |

## 2.5 SRT 标准化与台词维护（DLG）

| 编号 | 功能 | 状态 | 业务规则与验收要点 |
| --- | --- | --- | --- |
| DLG-001 | SRT 结构化解析 | 基线 | 将字幕条目转换为文本、顺序和起止时间，不依赖模型。 |
| DLG-002 | 多台词关联 | 基线 | 同一 Asset 可关联多条 Dialogue，多人对白无需拆成多个视频。 |
| DLG-003 | 相对视频时间 | 基线 | 时间基准为当前素材视频开头，不与原电影时间位置混用。 |
| DLG-004 | 台词文本编辑 | 基线 | 人工修正可保存，原始 SRT 保留，相关搜索结果随之更新。 |
| DLG-005 | 台词时间编辑 | 基线 | 可修正起止时间并校验有效性；不裁切视频、不改变视频长度。 |
| DLG-006 | 台词新增与删除 | 基线 | 可以维护工作台词条目；删条目不删除对应视频画面。 |
| DLG-007 | 台词顺序维护 | 部分待定 | 顺序明确可展示，编辑导致的排序、重叠处理规则待定。 |
| DLG-008 | 台词来源与校验状态 | 基线 | 区分导入字幕、人工修改及未来 AI 生成来源，标识人工校验情况。 |
| DLG-009 | 重新解析保护 | 基线 | 再次解析字幕不得默认覆盖人工修订，冲突需要明确处理。 |
| DLG-010 | 字幕缺失与失败区分 | 基线 | 无 SRT、SRT 无法解析和暂未完成处理分别可见，不统一记为没有台词。 |

字幕条目不必是一句完整自然语言句子。自动拆句、合句与说话人识别不作为本节默认交付功能。

| --- | --- | --- | --- |

| SRCH-010 | 空结果与索引异常区分 | 基线 | 没有匹配与索引未就绪或失败分别反馈，不能将异常伪装成无结果。 |

# 3. P1 语义与 AI 增强功能

# 6. 跨模块规则与状态边界

## 6.1 四类状态不混用

- 原始资源保存状态：是否已安全保存或建立有效引用，取决于最终托管策略。
- 标准化状态：是否具备规定的 Video、SRT、JSON 及一致的基础记录。
- 派生处理状态：缩略图、预览或全文索引各自是否可用。
- AI 增强状态：向量、情绪、视觉各自是否执行与成功。

具体枚举在流水线和数据模型文档中确定。AI 成功不代表来源可靠，缩略图失败也不代表视频原件不存在。

## 6.2 必须保持的业务关系

- Asset 是管理单位，Dialogue 是时间定位与文本检索单位。
- 台词命中返回所属 Asset 与时间范围，不默认新建片段。
- 标准三件套统一的是组织与信息结构，不是原始视频编码。
- 原始 SRT、可编辑 Dialogue、系统 JSON 需保持来源与更新关系，不可因修改台词就无提示覆盖原始字幕。
- JSON 与数据库谁作为各字段事实源、如何同步，在数据模型设计中明确，本文不预设双向自由覆盖。
- 工作台词修订后的字幕交付应与原始字幕区分；是否生成修订 SRT 及默认交付哪个版本待确认。
- 精确去重针对视频文件；补充信息冲突应单独处理。
- 不因模型替换、索引损坏或派生文件缺失要求重新导入整库。

## 6.3 最小可用性与原件保护

- 任一可选 AI 服务不可用，仍能完成标准 Video + SRT 的基础建库。
- 预览失败不丢失原始视频，不能对用户谎报可播放。
- 原始资源已保存后，后续失败要保留可追踪状态。
- 对已保存资源的破坏性删除必须显式确认，不作为普通编辑副作用。

# 8. 与后续设计文档的衔接

- 入库流水线：细化每阶段输入输出、状态、异常分级、恢复与重复处理边界。
- 数据库及数据模型：定义 Asset、Dialogue、文件、来源、任务、分析结果等实体，以及 JSON 版本与一致性规则。
- AI 模型与推理引擎：确定模型适配、输入依据、资源调度与结果生命周期。
- 搜索引擎：明确检索域、中文短查询、排序、融合、索引更新及重建行为。
- API 规范：覆盖核心功能编号，定义批量结果、错误、文件访问与外部边界。
- 页面与交互：将功能映射到入口，确定批量操作、配对、冲突、播放和失败提示。
- 目录结构：依据已确定职责组织实现，不在本清单中提前绑定技术栈。
- 分阶段开发与验收：仅对明确纳入范围的功能排期，建议与可选项需另行批准。
