Dialogue Library 产品需求文档
标准化台词视频素材库

文档版本：v0.1
文档状态：评审稿
适用范围：产品需求基线，不包含最终技术选型、数据库表结构及接口协议。

# 1. 产品概述

## 1.1 产品定位

Dialogue Library 是一个本地部署、支持可选 AI 增强、面向人工创作和自动化视频剪辑的标准化台词视频素材管理系统。

系统接收不同来源的已剪辑视频和对应字幕，通过固定的、无需 AI 模型参与的入库流程，形成结构统一、可管理、可检索、可交付的素材资产。

核心是“标准化台词素材库”，AI 是可选的素材准备与增强能力，不是基础系统的运行前提。

## 1.2 产品目标

- 统一组织来自不同渠道的台词视频与字幕，减少散落文件和重复资源。
- 将字幕转换为结构化台词，使素材能够被检索、定位和复用。
- 支持人工管理、浏览、播放、分类、删除和筛选素材。
- 为外部剪辑程序和 Agent 提供稳定、结构化的素材访问能力。
- 在不破坏原始资源的前提下，逐步增加语义检索与内容理解能力。

## 1.3 非目标

- 当前不负责从电影、剧集等长视频中自动生产素材。
- 不建设完整的时间线剪辑、转场、配乐和成片制作系统。
- 不依赖特定素材平台的账号、接口、链接或命名规则。
- 不保证自动识别作品、人物或素材授权情况。
- 不强制用户在导入前统一视频格式、编码、分辨率或文件名。

# 2. 目标用户与核心场景

## 2.1 人工创作者

用户拥有或准备收集台词视频，需要批量整理、搜索、预览和选用素材。

核心场景：

- 导入一批视频及配套字幕，建立可浏览的素材库。
- 按关键词找到台词，跳转播放对应位置。
- 按分类、标签、来源、收藏等条件筛选素材。
- 查看和修正台词、来源及其他信息。
- 后续通过含义、情绪或场景描述寻找素材。

## 2.2 自动化剪辑程序与 Agent

外部程序调用接口检索素材，获取视频、台词及时间范围，用于选片和后续剪辑。

Dialogue Library 负责提供可用素材与信息，不替下游程序完成整部作品的创作决策。

# 3. 产品边界

## 3.1 上游：非固定的素材准备

上游可以通过以下方式准备字幕：

- ASR 语音识别。
- OCR 画面字幕识别。
- 已有字幕提取。
- 人工字幕制作与校对。

这些方式可选择、可组合，不是必须依次执行的流水线，可以在系统之外完成。

若未来提供上述工具，应作为独立、可选的准备或补全能力，不成为基础入库的强制依赖。已有可用 SRT 时，不要求重新识别。

## 3.2 中游：固定的标准化入库与管理

系统负责校验、去重、媒体信息提取、字幕标准化、元数据构建、资源存储、数据库记录和检索索引，以及入库后的管理与使用。

## 3.3 下游：素材消费

- 人工检索、预览、挑选和获取素材。
- 外部程序或 Agent 通过接口检索并获取素材。

## 3.4 后续可选：长视频加工

长视频加工若实施，应产出可导入的候选素材资源，不自动收录到正式素材库。是否导入由用户决定，其后使用相同的标准入库流程。

# 4. 素材规范

## 4.1 标准输入

标准输入为：Video + SRT。

- Video：已剪辑、有效的视频文件，不要求统一容器、编码、分辨率或文件名。
- SRT：与视频对应的字幕文件，时间戳相对于当前视频。
- 配对不能以强制用户改名为前提；无法明确配对时需要用户确认。
- 本规范描述逻辑组成，不预设必须采用文件夹、压缩包或固定命名形式。

## 4.2 标准化存储格式

标准化存储格式为：Video + SRT + JSON。

- Video：保留原始视频内容。
- SRT：保留导入的原始字幕，作为台词来源之一。
- JSON：程序根据媒体信息、字幕及已提供信息构建的结构化元数据。

缩略图、兼容预览文件、全文索引和向量索引属于关联的派生资源，不属于标准存储三件套。

用户已有 JSON 可作为可选的补充输入，但不是标准输入的必需部分。其字段接受、校验与合并规则待数据模型设计确定。

## 4.3 仅视频资源的边界

此前已明确：最低资源接纳条件是有效的独立视频，其他信息可后续补全。之后又确定了 Video + SRT 标准输入。

本稿建议区分：

- 仅 Video：允许保存、管理，标记为字幕待补全，不能显示为完整标准化素材。
- Video + SRT：进入完整的标准化入库流程。
- Video + SRT + JSON：达到标准化存储要求。

上述状态命名、是否提供独立待补全入口及正式素材列表展示规则，属于待确认项，不视为已批准方案。确认前不得擅自把 SRT 缺失变成原始视频丢弃条件，也不得自动启动 ASR。

## 4.4 素材与台词关系

素材的管理单位是视频 Asset，不是单句台词。

允许：

- 单句台词视频。
- 多句台词或多人对话视频。
- 包含台词前后画面的视频。

一个 Asset 对应零条或多条 Dialogue。零条可用于字幕未补全或处理未完成的状态，不表示已确认允许无台词内容作为完整标准素材。

每条台词有独立文本、顺序及起止时间。字幕条目不强制等同于自然语言的一句话；拆分、合并及多人对白规则后续确定。

入库不自动去掉台词前后画面。搜索命中台词不等于自动生成新的裁切文件。

# 5. 数据分层原则

## 5.1 原始素材

用户导入的视频、SRT，以及可选原始 JSON。

- 保留原始内容。
- 不被分析、编辑或预览兼容处理覆盖。
- 与解析和增强结果保持关联。

## 5.2 基础元数据与派生资源

程序提取或构建的哈希、媒体属性、结构化台词、标准 JSON，以及缩略图和预览文件等。

其中，来自 SRT 的结构化台词不属于 AI 生成结果；它不依赖模型。

可重建结果与人工修订必须区分。修正台词时保留原始 SRT，不因重新解析而默认覆盖人工修改。

## 5.3 AI 增强数据

语义向量、情绪分析、视觉理解等可选结果。

- 分别记录模型版本、输入依据和处理状态。
- 可独立生成、失败重试、替换与更新。
- 失败不影响基础素材管理。

## 5.4 人工维护信息

标题、分类、标签、收藏、来源及人工修订内容属于需要持续保留的业务数据，不能因为重建索引或更换模型而丢失。

# 6. 固定入库流程

## 6.1 素材校验与哈希去重

- 检查视频有效性和媒体可解析性。
- 检查 SRT 格式、视频配对、时间顺序和时间范围。
- 计算视频内容哈希，检查批次内、已保存及处理中资源的重复。
- 重复文件不重复存储、不重复启动相同处理。
- 同视频附带新的字幕或来源信息时，提示补充或冲突，不静默覆盖人工修订。
- 无法处理的文件说明原因，不显示为处理成功。

时间戳异常的阻断级别、空字幕及部分错误的处理策略待流水线设计确认。不得无提示修改字幕内容或时间。

## 6.2 媒体信息提取

- 提取时长、编码、分辨率、帧率及音轨等信息。
- 生成缩略图。
- 检测播放兼容性，必要时生成兼容预览副本。
- 区分原视频属性与预览文件属性。
- 预览副本保持与原视频的时间对应，避免台词定位错位。

## 6.3 字幕标准化

- 解析 SRT，生成结构化 Dialogue。
- 保留顺序、文本及相对当前视频的起止时间。
- 记录字幕来源与人工校验状态。
- 标准化结果与原始 SRT 分开保存，不覆盖原件。

## 6.4 元数据构建

合并媒体信息、台词及已提供的业务信息，生成 JSON。

基本内容包括素材标识、标题、语言、媒体属性、台词数组、来源、分类和标签等。具体字段和必填规则在数据模型设计阶段确定。

缺少来源、作品名或授权依据时，应保留未知，不调用模型猜测来满足字段完整性。

## 6.5 素材存储

保存标准三件套及关联派生资源，保证关联关系可追溯。

原始资源已保存后，后续缩略图、预览或索引生成失败不应造成原始资源丢失。

## 6.6 数据库入库与全文索引

- 建立素材及台词记录。
- 建立支持关键词搜索的索引，无需语义模型。
- 保存处理阶段、结果及失败原因。
- 只有达到约定条件的项目才显示为标准化完成。
- 文件、JSON、数据库和索引之间的一致性需要可检查、可修复。

以上为逻辑流程，不规定实现时必须等到最后才写入任何数据库记录；任务跟踪和异常恢复可以提前保存必要状态。

# 7. 功能范围与优先级

## 7.1 P0：基础素材库

| 一级模块 | 二级功能 | 需求说明 |
| --- | --- | --- |
| 素材导入 | 文件导入、目录扫描、批量导入 | 用户确认后处理；扫描不等于自动收录 |
| 素材存储 | 文件管理、哈希去重、完整性检查 | 保护原件，识别缺失或异常资源 |
| 媒体解析 | 时长、编码、分辨率、缩略图 | 自动识别，按需生成兼容预览 |
| 台词解析 | 字幕提取、台词时间戳、可选语音识别辅助 | 基础入库以 SRT 解析为准；ASR 不作为必经步骤 |
| 素材管理 | 编辑、删除、分类、标签、收藏 | 支持单条管理和必要的批量操作 |
| 素材检索 | 关键词搜索、组合条件筛选 | 支持台词检索及素材级筛选 |
| 素材预览 | 视频播放、台词展示 | 点击台词定位播放 |
| 素材溯源 | 来源、影视名称、授权信息 | 未知信息明确标识 |
| 任务管理 | 批量处理、进度、失败重试 | 后台运行，单条失败不阻塞整批 |

优先级说明：早期功能清单将 ASR 列为 P0；按最新产品边界，ASR 调整为可选准备能力，不是基础 P0 交付的验收前提。是否在首版提供辅助 ASR 工具，需另行确认。OCR 同样不自动纳入首版范围。

## 7.2 P1：语义与 AI 增强

| 一级模块 | 二级功能 | 需求说明 |
| --- | --- | --- |
| 语义检索 | Embedding、向量检索、混合检索 | 支持按含义找素材，保留关键词检索 |
| AI 内容理解 | 情绪、主题、动作、场景分析 | 按需运行，结果可查看和修正 |
| 对外服务 | REST API、Agent 工具接口 | 完善外部使用契约、说明和适配 |

API 优先从基础阶段生效；P1 对外服务不代表 P0 业务只能通过 UI 操作。

## 7.3 P2：后续扩展

| 一级模块 | 二级功能 |
| --- | --- |
| 高级去重 | 相似画面、相似音频检测 |
| 人物管理 | 人物聚类、跨片段关联 |
| 素材推荐 | 相似台词、关联素材推荐 |
| 二次剪切 | 已有素材的时间范围调整 |

二次剪切生成派生文件，不覆盖原始视频。长视频加工仍属于另行评估的可选范围，不因列入后续讨论而默认承诺交付。

# 8. 素材管理页面

提供管理、浏览、播放、分类、删除和筛选素材的主要入口。

## 8.1 素材列表

- 以 Asset 展示，包含多句台词的视频不重复显示为多条素材。
- 展示缩略图、标题、时长、台词摘要、分类及处理状态。
- 支持关键词搜索和组合筛选。
- 支持分类、标签、收藏以及单条或批量删除等操作。
- 命中多句台词时展示命中摘要，定位到同一素材的对应位置。

## 8.2 素材详情

- 视频播放与台词同步展示、定位。
- 编辑标题、描述、分类、标签及来源信息。
- 查看与编辑多条台词的文本和时间。
- 查看原媒体属性及预览资源状态。
- 查看任务失败原因并重试。
- 后续展示可选 AI 分析及人工修订状态。

删除台词记录不等于删除视频画面，修改台词时间不等于二次剪切。

## 8.3 删除保护

删除前明确展示操作影响范围，区分库内记录、托管文件、派生文件和外部原文件。不得因常规素材编辑而删除或修改外部原件。回收站、恢复和彻底删除规则待确认。

# 9. 可选 AI 增强流程

## 9.1 语义向量

基于台词及可用描述生成检索向量，支持含义查询、混合检索及相似素材查找。无需等待情绪和视觉分析完成。

## 9.2 情绪分析

分析情绪、语气和表达意图，区分文本推断与实际视听依据。按需要区分单句台词结果与整段素材结果。

## 9.3 视觉理解

分析场景、人物动作、镜头类型，形成可查看和修改的标签与描述。不无依据推断人物身份和来源作品。

## 9.4 通用规则

- 三项能力独立启用，不强制全部执行或固定串行。
- 支持选择素材范围并在后台处理。
- AI 失败不影响基础入库、关键词检索及人工管理。
- 更换模型不需要重新导入视频。
- 重建向量与索引不应破坏人工修订。

# 10. 产品与质量约束

## 10.1 来源无关

不绑定任何特定平台。来源平台只是可选业务信息。

## 10.2 本地优先

视频、字幕、JSON、数据库和索引保存在本地。基础建库和使用不依赖在线 API 或 AI 模型。

## 10.3 模型可插拔

可选 ASR、Embedding、视觉模型允许独立替换，不能成为素材文件格式的隐含依赖。

## 10.4 异步与可恢复

批量导入和耗时处理不阻塞用户操作。任务进度与失败原因可见，应用中断后能够识别未完成任务，并恢复或重试。

## 10.5 增量处理

新增 100 个视频只处理新增及受影响资源，不重新分析全库。修改收藏或分类不触发语音识别；修改台词只更新相关元数据、索引及必要增强结果。

## 10.6 索引可重建

全文和向量索引可从保留的数据重建。更换 Embedding 模型需要生成匹配的新向量，不能默认混用不同模型的向量。

## 10.7 API 优先

导入、查询、编辑、删除、任务查询与重试等核心业务能力均可通过接口调用，不限定为 UI 内部能力。接口细节另行设计。

## 10.8 原始素材保护

AI 分析、标签修改、兼容预览及二次剪切不覆盖原视频。派生资源与原件可区分，人工修订不因重新处理而静默丢失。

## 10.9 支持边界

不要求用户预处理，不等于支持任意损坏、加密或未知格式。无法处理时明确说明原因，并允许其他有效资源继续处理。

## 10.10 量化指标

素材规模、搜索延迟、导入吞吐、磁盘预算与并发数量尚未确定。后续基于目标设备和真实样本制定，不将未测试数字写成承诺。

# 11. 产品级验收标准

## 11.1 基础闭环

- 给定有效视频与配对 SRT，在没有 AI 模型和在线 API 的条件下完成标准化入库。
- 生成与视频关联的结构化 JSON、Asset 及多条 Dialogue。
- 能够浏览、播放、分类、删除及组合筛选素材。
- 能按字幕关键词查找素材，并定位播放命中的台词。
- 不要求用户修改文件名、分辨率、编码或容器后再导入。

## 11.2 数据正确性与保护

- 相同视频不重复存储，不重复执行相同处理任务。
- 多句台词视频仍是一个 Asset，台词时间相对当前视频。
- 原始视频和原始字幕不被常规解析、编辑或兼容处理覆盖。
- 生成预览副本后仍能正确定位台词。
- 重建全文索引不要求重新导入视频，也不丢失人工维护信息。

## 11.3 异常与增量处理

- 批次内单条失败不阻塞其他资源。
- 文件异常、字幕错误、配对不明和重复情况均有明确反馈。
- 失败项可重试，已完成内容不被无故重复处理。
- 新增资源不触发整个素材库重建。
- 缩略图或预览失败时，原始资源不丢失且状态可见。

## 11.4 可选 AI 增强

- 未启用 AI 时，基础功能完整可用。
- 启用后可按选定范围执行语义向量、情绪或视觉分析。
- AI 分析失败不影响已有基础素材。
- 更换模型不需要重新导入原视频，不默认覆盖人工修订。
- 检索质量使用真实素材和查询样本评估，不仅以接口返回结果作为成功标准。

# 12. 待确认项与后续设计

## 12.1 PRD 评审需确认

1. 仅 Video 的资源接纳方式：待补全状态、入口及正式列表展示规则。
2. 文件托管方式：复制到库内、引用原路径，或允许两种模式。
3. 重复视频附带新 SRT、JSON 或来源信息时的补充与覆盖规则。
4. 异常 SRT、无台词视频及空字幕是否允许达到完整标准化状态。
5. 删除范围、回收站与恢复规则。
6. 分类是否单选、多选或分层。
7. 首版是否包含可选 ASR 辅助工具；不影响无需 AI 建库的基线。
8. 使用范围是单用户本机，还是需要局域网多客户端访问。
9. 预期素材规模与量化验收指标。
